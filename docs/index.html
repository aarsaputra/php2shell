Anatomi Bug & Versi Terpengaruh

Dua kerentanan PHP kritis unauthenticated yang diumumkan Oktober 2026. Toolkit ini mengimplementasikan rantai eksploitasi penuh untuk CVE-2026-109619.

Zero Target-Side Requirements

Rantai exploit tidak membutuhkan prasyarat aplikasi target:

  • TIDAK butuh fungsi session_start() pada skrip target
  • TIDAK butuh fitur upload file apapun di aplikasi
  • TIDAK butuh autentikasi, cookies, atau trik header
  • Endpoint target cukup berupa satu baris: <?php echo "OK\n"; ?>

Fix-Floor & Status Branch

Bila versi PHP target di bawah fix-floor, sistem rentan:

• PHP 8.4: Rentan ≤ 8.4.26 · Patch: 8.4.27
• PHP 8.3: Rentan ≤ 8.3.35 · Patch: 8.3.36
• PHP 8.2: Rentan ≤ 8.2.34 · Patch: 8.2.35
• PHP 8.5: Rentan ≤ 8.5.11 · Patch: 8.5.12
• PHP ≤ 8.1: EOL (End of Life) — Rentan permanen

Catatan Advisori Resmi

Patch PHP dibangun ulang 22 Okt 2026. memory_limit=-1 BUKAN mitigasi lengkap (GHSA-w8hw-w9fx-j79w). Menonaktifkan session.upload_progress.enabled=0 hanya menutup CVE-2026-109618, tidak menutup CVE-2026-109619.

CAPABILITIES

Fitur Utama & Karakteristik

Dibangun dengan filosofi riset defensif dan kendali ketat — membuktikan dampak nyata tanpa senjata perusak bebas.

Proof-of-Access by Design

Perintah eksekusi dibatasi ketat maksimal 14 byte dan difokuskan pada perintah identitas (id, whoami). Ekstraksi bukti hasil perintah terbaca otomatis via channel lab.

  • Whitelist aman: id, whoami, uname, hostname
  • Permanen memblokir bash, nc, curl, wget, piping
  • Reverse shell dieliminasi total dari kode dasar

Stealth JA3 / TLS Transport

Mengintegrasikan curl_cffi untuk menirukan fingerprint TLS browser asli (Chrome, Safari, Firefox, Edge, Android) guna menghindari blokir WAF bot-mitigation biasa.

  • Impersonasi TLS/JA3 + HTTP/2 frame headers
  • Timing manusiawi dengan delay + random jitter (0.75×–1.35×)
  • Audit trail lokal: rekaman detail setiap request ke file JSONL

Deteksi Aktif OOM (v1.4.0+)

Mendeteksi target yang menyembunyikan versi di balik CDN menggunakan metodologi riset Assetnote / Searchlight Cyber dengan kunci nested-62 level (1 -> 8 -> 20 MiB).

  • Analisis fatal OOM di dalam parser multipart
  • Deteksi differential empty HTTP 500 & worker abort
  • Proteksi false-positive terhadap post_max_size guards

Adaptive Memory Tuning

Secara cerdas membaca memory_limit target melalui 1 request probe sebelum eksploitasi, lalu menyesuaikan ukuran field multipart stage-1 secara dinamis.

  • Otomatis set field multipart di atas limit target
  • Validasi dini prasyarat post_max_size ≥ 64M
  • Berhenti dalam ~2 detik jika batas memori target > 512 MB

Build Support Matrix

Memuat tabel 13 profil heap PHP terverifikasi (dari riset devploit & lab 9bie). Menjawab tegas apakah target berada pada tingkat RCE penuh atau sekadar leak memori.

  • Klasifikasi dukungan: RCE, LEAK, NO, atau Unknown
  • Membedakan arsitektur target: amd64 vs aarch64
  • Dukungan custom offset manual (--zif-offset)

Secure Webshell Generator

Generator payload webshell berkeamanan tinggi dengan hash password bcrypt, batasan whitelist perintah ketat, dan masa aktif kedaluwarsa otomatis (TTL).

  • Generator standalone di subfolder shell/ (tanpa auto-upload)
  • Hashing password dengan bcrypt aman
  • Kedaluwarsa otomatis (default TTL 72 jam)
UNDER THE HOOD

Alur Kerja Eksploit & Arsitektur Modul

Bagaimana bug UAF dikonversi menjadi remote code execution in-process murni HTTP, serta pemetaan komponen modul toolkit.

1

Stage 1: Producer (OOM Trigger)

Request A mengirim payload multipart berukuran 12MB+ sebelum RINIT. Menyebabkan OOM pada php_session_initialize(), meninggalkan PS(http_session_vars) dangling. Worker Apache prefork mati karena SIGABRT.

2

Stage 2: Consumer (ASLR Bypass)

Apache prefork melakukan fork worker baru yang mewarisi layout memori dan mapping libphp yang identik. Request B mengklaim ulang pointer dangling via multipart buffer dan membaca leak 4096-byte Set-Cookie guna mengalahkan ASLR.

3

Stage 3: Actuator (Fake HashTable)

Menyuntikkan struktur carrier fake HashTable dengan pDestructor = zif_system. Saat Apache membersihkan session di zval_ptr_dtor(), fungsi destruktor memanggil system() dengan payload perintah aman.

Prinsip Desain Modular

Seluruh engine rantai eksploitasi diimplementasikan secara in-process dalam bahasa Python murni tanpa bergantung pada binary eksternal seperti curl, gcc, atau readelf.

  • Zero Spawning: Tidak menjalankan child process untuk exploit HTTP
  • In-Process ELF Parsing: Membaca offset symbol ELF via modul Python struct internal
  • Offline Capable: Seluruh modul transport & payload dapat beroperasi tanpa koneksi internet ke repo eksternal
  • Test-Covered: 46/46 unit tests memvalidasi pagar eksekusi, format output, dan deteksi SAPI sebelum digunakan
Integrity Check:
Checksum SHA-256 dari lib/chain.py diverifikasi pada setiap peluncuran untuk memastikan integritas engine payload.
GETTING STARTED

Panduan Instalasi & Persiapan

Tiga tingkat ketergantungan. Tool inti hanya butuh Python 3.9+ dan 2 dependensi ringan.

01. One-Shot Installer (Disarankan)

Menyiapkan virtual environment, memasang dependensi, menjalankan smoke test, dan membuat perintah global php2shell.

Terminal Bash 
git clone https://github.com/aarsaputra/php2shell.git
cd php2shell
bash install.sh
• Opsi tanpa symlink global: bash install.sh --no-bin
• Jalankan tanpa hak akses root (non-sudo).
02. Manual Virtual Environment

Pemasangan standar menggunakan pip untuk environment terisolasi.

Terminal Bash 
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python php2shell.py --help
• Hanya membutuhkan curl_cffi (JA3) dan bcrypt.
• Target yang mengeksekusi PHP; mesin attacker tidak wajib ada PHP.
03. One-Command Docker Lab

Menjalankan environment riset resmi dengan konfigurasi rentan mod_php Apache 8.4.26.

Terminal Bash 
bash lab/lab_docker.sh start
python3 docker/offsets.py
php2shell exploit -u http://127.0.0.1:8095/index.php \
  --force --yes --exploit-profile bookworm -c 'id>/out/p1'
• Mengunduh image resmi php:8.4.26-apache.
• Mengonfigurasi single worker prefork & mem-mount folder /out.
COMMAND LINE INTERFACE

Mode Pemakaian CLI & Contoh Perintah

Pilih salah satu mode kerja di bawah untuk melihat sintaks perintah, opsi flag utama, dan contoh respons terminal.

Mode Scan: Memindai banyak target sekaligus dari file daftar teks (-l targets.txt). Melakukan detect dan preflight secara paralel dengan dukungan ekspor laporan JSON dan CSV.

Contoh Perintah CLI 
# Pindai banyak URL secara paralel dengan 10 threads dan simpan laporan
php2shell scan -l targets.txt --threads 10 --json out/report.json --csv out/report.csv

# Pindai dan langsung exploit target yang berstatus READY saja
php2shell scan -l targets.txt --exploit --yes --cmd id
-l, --list FILEFile berisi daftar URL (satu URL per baris, auto de-duplicate)
--threads NJumlah worker thread pemindaian concurrent (default: 5)
--exploit --yesLanjutkan eksekusi otomatis hanya terhadap target yang berstatus READY
--json / --csv PATHLokasi penyimpanan file laporan hasil scan

Mode Detect: Intip informasi versi PHP, status upload_progress, dan display_errors target secara read-only tanpa melakukan penyerangan exploit.

Contoh Perintah CLI 
# Deteksi pasif standar via GET header
php2shell detect -u https://target.example/

# Deteksi dengan OOM aktif otomatis untuk target CDN/unknown
php2shell detect -u https://target.example/

# Matikan deteksi aktif OOM probe
php2shell detect -u https://target.example/ --no-oom
-u, --urls URLSatu atau lebih URL target yang akan dideteksi
--no-oomMatikan pengiriman probe OOM bertingkat (1/8/20 MiB)
--sapi {auto,fpm,mod_php}Filter pembacaan sinyal crash (default: auto)
--check-versionBandingkan versi lokal dengan repositori GitHub sebelum mendeteksi

Mode Preflight: Memberikan kalkulasi skor kesiapan exploit (0–90) dan mendeteksi kondisi blocker. Deteksi adalah informasi, bukan penghalang jalan.

Contoh Perintah CLI 
# Hitung skor kesiapan target
php2shell preflight -u https://target.example/

# Tampilkan rincian koneksi HTTP secara mendetail
php2shell preflight -u https://target.example/ -v
Skor 30 PoinVersi PHP terkonfirmasi di bawah fix-floor yang rentan
Skor 30 PoinDirektif session.upload_progress.enabled terdeteksi On
Skor 15 Poindisplay_errors aktif (membocorkan heap / memory error)
Skor 15 PoinFormat versi dikenali secara presisi

Mode Exploit: Mengeksekusi rantai penuh 3-stage (heap leak, ASLR defeat, fake HashTable carrier). Membutuhkan konfirmasi tegas --yes.

Contoh Perintah CLI 
# Skenario Lab Lokal (Hasil perintah terbaca via mount /out)
php2shell exploit -u http://127.0.0.1:8095/index.php --force --yes \
    --exploit-profile bookworm -c 'id>/out/p1'

# Skenario Target Live (Blind by design — verifikasi via worker restart)
php2shell exploit -u https://target.example/ --yes -c 'id'
-c, --cmd CMDPerintah identitas maks 14 byte (default: id; disaring whitelist ketat)
--forceAbaikan peringatan preflight belum ready (tetap meminta konfirmasi)
--exploit-profileProfil offset bawaan image (mis. bookworm untuk image resmi)
--zif-offset / --dtor-offsetPasok offset alamat simbol biner libphp kustom secara manual

Mode Shell: Menghasilkan file webshell PHP berkeamanan tinggi dengan credential hash bcrypt, nama acak 32-hex, dan kedaluwarsa TTL. Generator murni (tidak melakukan upload).

Contoh Perintah CLI 
# Generate webshell dengan masa berlaku 72 jam ke folder shell/out
php2shell shell --out shell/out --ttl 72

# Tentukan daftar perintah yang diizinkan dieksekusi di webshell
php2shell shell --out shell/out --ttl 48 --commands "id,whoami,uname,df"
--out DIRFolder tujuan keluaran webshell dan file CREDENTIALS.txt
--ttl HOURSMasa berlaku webshell dalam hitungan jam sebelum kedaluwarsa (default: 72)
--commands LISTDaftar whitelist perintah yang diizinkan (default: id,whoami)

Mode Builds: Menampilkan tabel verifikasi 13 profil heap PHP. Membantu menentukan apakah target terbukti bisa di-RCE atau hanya sampai tahap memory leak.

Contoh Perintah CLI 
# Tampilkan semua tabel profil build PHP
php2shell builds

# Filter hanya build yang terbukti sukses dieksekusi RCE
php2shell builds --level rce
Status RCEStage 1, 2, dan 3 terbukti sukses di arsitektur tersebut
Status LEAKStage 1 & 2 terbukti (leak alamat memori), stage 3 belum berhasil
Status NOBelum pernah terbukti bisa dilanjutkan pada konfigurasi default

Mode Version: Membandingkan versi toolkit lokal dengan rilis terbaru di repositori GitHub secara fail-safe tanpa telemetri data.

Contoh Perintah CLI 
# Cek versi vs rilis terbaru GitHub
php2shell version

# Abaikan cache 1 jam dan paksa fetch informasi rilis terbaru
php2shell version --no-cache
Fail-SafeTidak pernah crash atau menggagalkan pipeline bila offline atau GitHub limit
Tanpa TelemetriMurni HTTP GET publik ke GitHub API tanpa mengirim data apapun
Exit Code 10Mengembalikan kode keluar 10 bila terdapat update baru (cocok untuk gate CI)
CRITICAL UNDERSTANDING

Lab Target vs. Live Target

Dua skenario dengan ekspektasi hasil dan perintah yang sengaja dibedakan berdasarkan filosofi proof-of-access.

Skenario A: Lab Lokal (127.0.0.1)

Full Proof

Pada lab pengujian docker lokal, folder /out di dalam kontainer di-mount langsung ke direktori mesin host (out/p1). 

php2shell exploit -u http://127.0.0.1:8095/index.php \
    --force --yes --exploit-profile bookworm -c 'id>/out/p1'
# PROOF (8.3s): uid=33(www-data) (Output terbaca otomatis)
Karena folder di-mount bersama, toolkit dapat membaca file pembuktian dan menampilkan bukti user ID www-data secara langsung di layar terminal.

Skenario B: Live Target (Blind by Design)

Blind by Design

Pada server live target, folder /out milik server tidak terhubung ke mesin penguji. Perintah dieksekusi tetapi output tidak dialirkan balik. 

php2shell exploit -u https://target.example/ --yes -c 'id'
# Stage 1, 2, 3 selesai, tapi:
# BLIND: Perintah terkirim tanpa kanal ekstraksi data!
Keputusan Desain Sadar: Membuat kanal membaca output pada target jauh sama artinya dengan membangun tool ekstraksi data (backdoor). Toolkit sengaja berhenti pada bukti eksekusi (worker crash pattern di log + stage-3 completion).

5 Prasyarat Kalibrasi Lab (The 5 Lab Requirements)

1. MaxRequestWorkers 1: Memastikan producer & consumer mendarat pada worker Apache yang sama.
2. KeepAlive Off: Menghindari koneksi persisten yang mengacaukan rotasi worker.
3. Fresh offsets.env: Offset usang adalah penyebab kegagalan hening terbesar.
4. upload_progress.cleanup = On: Trigger pembersihan session struktural.
5. Minimal Endpoint: Cukup file uji sederhana echo "OK";.
ETHICS & GOVERNANCE

Kebijakan Keamanan, Pagar & Batasan Hukum

Pagar perlindungan ditegakkan langsung di level kode (hard-coded fence), bukan sekadar teks peringatan dokumentasi.

Pagar Eksekusi Ditegakkan di Level Kode

Toolkit ini tidak dapat dimodifikasi lewat argumen baris perintah untuk meluncurkan serangan berbahaya tak terkendali. Pembatas diverifikasi pada lib/exploit_runner.py sebelum paket data dikirim ke jaringan:

Maksimal 14 Byte

Payload dibatasi hanya muat untuk perintah pembuktian identitas sederhana seperti id atau whoami.

Anti-Chaining Operators

Karakter berbahaya seperti ;, |, &, $, `, >, dan < ditolak seketika oleh runner.

No Reverse Shell

Flag --revshell dan listener netcat dieliminasi total dari kode dasar untuk mencegah penyalahgunaan backdoor.

Pernyataan Hukum & Batasan Penggunaan

Alat ini didistribusikan untuk keperluan riset defensif, pengujian blue-team, dan verifikasi patch keamanan pada sistem yang telah Anda miliki izin tertulis untuk diuji. Menguji atau mengeksploitasi sistem pihak ketiga tanpa izin adalah pelanggaran hukum berat (Undang-Undang Informasi dan Transaksi Elektronik / UU ITE di Indonesia, US CFAA, dan peraturan cybercrime internasional lainnya).
