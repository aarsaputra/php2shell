## Kandidat lolos filter (untuk verifikasi ASAN/dinamis lanjutan)

### K-1-a — Spoofchecker: jalur `zend_objects_store_del` ganda saat clone gagal (uspoof_clone throws)
- **Bentuk:** `spoofchecker_clone_obj` (`ext/intl/spoofchecker/spoofchecker_class.c:62-83`). Range: baris 74-77 — `if (U_FAILURE(error))` → `Spoofchecker_objects_free(&spoofchecker_new->zo)` dipanggil **langsung** pada objek baru yang sebelumnya dibuat via `create_object` (refcount 1, belum pernah ke store), lalu melanjutkan `return new_obj_val` dengan status error pending.
- **Pola:** jalur double-teardown yang kini **terkonfirmasi statis** (jejak VM lengkap). `Spoofchecker_objects_free` (baris 30-37) adalah `free_obj` handler yang seharusnya hanya dieksekusi via `zend_objects_store_del` dengan guard flag `IS_OBJ_FREE_CALLED` (`Zend/zend_objects_API.c:193`). Pemanggilan manual melewati guard itu. Jejak lengkap saat `uspoof_clone` gagal:
  1. `spoofchecker_clone_obj` memanggil `Spoofchecker_objects_free(&spoofchecker_new->zo)` manual (baris 76) → `zend_object_std_dtor` + `spoofchecker_object_destroy` jalan **pertama**, flag `IS_OBJ_FREE_CALLED` TIDAK di-set (yang set flag hanyalah `zend_objects_store_del`).
  2. `zend_throw_error` (baris 77) — tidak unwinding; handler clone `return new_obj_val`.
  3. `ZEND_CLONE` (`Zend/zend_vm_def.h:5998`) sudah menulis `ZVAL_OBJ(EX_VAR(opline->result.var), clone_call(zobj))` sebelum cek exception; `ZEND_VM_NEXT_OPCODE_CHECK_EXCEPTION()` melihat `EG(exception)` → `HANDLE_EXCEPTION` → `cleanup_live_vars` (`Zend/zend_execute.c:4690`).
  4. Slot hasil adalah live-range `ZEND_LIVE_TMPVAR` → `zval_ptr_dtor_nogc(var)` (`zend_execute.c:4715-4716`) → `OBJ_RELEASE` → refcount 1→0 → `zend_objects_store_del` → karena flag `IS_OBJ_FREE_CALLED` belum ada → `free_obj` (`Spoofchecker_objects_free`) jalan **kedua** + `efree` object block.
  5. `zend_object_std_dtor` TIDAK idempoten (`Zend/zend_objects.c:77-109`): eksekusi kedua = dtor dynamic-properties HashTable dua kali (double-release HT), dtor `properties_table` dua kali (double-refcount-decrement semua properti terdeklarasi), dan dtor guards dua kali (`USE_GUARDS`).
- **Trigger yang menajamkan dampak:** pada `Spoofchecker` polos (tanpa properti) kerusakan minim; pada **subclass user dengan properti terdeklarasi** (`class MySpoof extends Spoofchecker { public $arr = []; }`) dtor ganda properti = double-refcount-decrement pada zval yang dipegang → UAF nyata mengikuti pembebasan kedua.
- **Mengapa bukan silent fix 8.4.26→27:** `spoofchecker_class.c` tidak ada di daftar 300 file yang berubah. Cek master `php-src` (fetch `ext/intl/spoofchecker/spoofchecker_class.c` @ `php-src/master`, 2026-10-25): pola `uspoof_clone` → `Spoofchecker_objects_free(&...->zo); zend_throw_error(...)` masih persis sama → PHP belum memperbaiki ini hingga master.
- **Filter:**
  1. COW/aliasing? Tidak ada COW — ini objek internal ICU (`USpoofChecker*`), bukan zend_string/array.
  2. Akses per-nama / per-iterasi? Trigger-nya adalah satu langkah `clone $sp` (per-statement), bukan per-iterasi.
  3. User code bisa jalan di tengah frame? Tidak diperlukan pada jalur utama — unwind VM (`cleanup_live_vars`) murni internal; user code hanya relevan via subclass bertipe-properti (item 5 pola) yang menentukan *apa* yang rusak.
  4. Guard eksisting? Tidak memadai — `IS_OBJ_FREE_CALLED` hanya di-set oleh `zend_objects_store_del` (`zend_objects_API.c:176,193-196`), sehingga pemanggilan manual `Spoofchecker_objects_free` di baris 76 membuat panggilan `store_del` kedua tidak terlindungi.
  5. Global atau milik objek? Milik objek (`Spoofchecker_object*` fresh hasil `create_object`, refcount 1, belum dibagikan ke store/temp lain).
- **Pre-kondisi yang diperlukan untuk trip:** `uspoof_clone()` gagal (mengembalikan NULL dengan `U_MEMORY_ALLOCATION_ERROR` atau failure ICU internal lain). Tidak ada jalur user-controllable yang dapat memaksa `uspoof_clone` gagal dari API PHP statis — `Spoofchecker::__construct` hanya set atribut via setter (`setAllowedLocales`/`setChecks`/`setRestrictionLevel`), dan `uspoof_clone` dari objek valid praktis selalu sukses kecuali kondisi OOM/alokasi ICU gagal. Rantai pemicu alokasi-gagal-tertarget belum ditelusuri — perlu eksperimen runtime (OOM-engineering / hook alokasi ICU).
- **Verdict: (a) unknown-unknown (kandidat kuat, mekanisme terbukti statis).** Dua-duanya — free_obj ganda dan non-idempotensi `zend_object_std_dtor` — sudah diverifikasi dari source Zend itu sendiri; yang tersisa hanya memaksa `uspoof_clone` gagal di runtime untuk trip ASAN. Bukan silent-fix 8.4.27, belum diperbaiki di master, tidak ditemukan laporan publik. Wajib reproduksi ASAN sebelum lapor ke bugs.php.net; tanpa trip, tetap kandidat.

### Bersih dengan bukti (bukan sekadar tidak menemukan) — pola R2 yang sudah dipastikan tidak rawan

1. **Semua clone handler kelas intl lainnya sudah dicek satu per satu dan handal** (`Calendar_object_clone` calendar_class.cpp:78, `IntlDatePatternGenerator_object_clone` datepatterngenerator_class.cpp:37, `NumberFormatter_object_clone` formatter_class.c:61, `IntlDateFormatter_object_clone` dateformat_class.c:65, `MessageFormatter_object_clone` msgformat_class.c:57, `Transliterator_clone_obj` transliterator_class.c:129, `TimeZone_clone_obj` timezone_class.cpp:227, `BreakIterator_clone_obj` breakiterator_class.cpp:97, `php_converter_clone_object` converter.c:936): semuanya buat objek baru via `create_object` (fresh `zend_object_alloc` + `create_object` re-init semua ICU pointer ke NULL) sebelum `zend_objects_clone_members` — jadi tidak ada kemungkinan pointer mentah ICU ikut ter-copy shallow dari objek asal. Kelas yang tidak mendukung clone (`Collator`, `ResourceBundle`, `IntlIterator`, `PgSql\Connection/Result/Lob` di ext/pgsql, `IntlDatePatternGenerator` subgroup) semuanya eksplisit `clone_obj = NULL` — tidak ada shallow-copy pointer mentah via `zend_objects_clone_members` default.
2. **`intl_error` (struct `custom_error_message` + flag `free_custom_error_message`)** kandidat awal untuk shallow-copy — gugur: field ini tidak di-copy oleh `zend_objects_clone_members` (struct ini hidup *di dalam* objek ICU-wrapper C, bukan sebagai property zend_object terdaftar); objek hasil clone dari `create_object` selalu memulai dengan `intl_error_init`/reset sehingga tidak ada duplikat pointer ke buffer pesan yang sama.
3. **`BreakIterator_object.compiled_rules` (`zend_string*`)** kandidat rawan disimpan melebihi umur pemilik — gugur: di-clone eksplisit via `zend_string_copy` (`breakiterator_class.cpp:112-114`), di-release di free (`breakiterator_class.cpp:184-186`), tidak ada jalur kedua yang bisa menghapus `zend_string` asal sebelum clone; `bio->text` (`zval`) juga di-`ZVAL_COPY` eksplisit.
4. **Guard un-construction (R4) sudah lengkap di semua kelas metode-fetch** — semuanya cek `NULL` sebelum menyentuh handle: `FORMATTER_METHOD_FETCH_OBJECT` (formatter_class.h:43-49), `TRANSLITERATOR_METHOD_FETCH_OBJECT` (transliterator_class.h:51-57), `TIMEZONE_METHOD_FETCH_OBJECT` (timezone_class.h:60-65), `SPOOFCHECKER_METHOD_FETCH_OBJECT` (spoofchecker_class.h:65-70), `RESOURCEBUNDLE_METHOD_FETCH_OBJECT` (resourcebundle_class.h:40-45), `INTLITERATOR_METHOD_FETCH_OBJECT` (common_enum.h:40-46), `CALENDAR_METHOD_FETCH_OBJECT` (calendar_class.h:54-60), `BREAKITER_METHOD_FETCH_OBJECT` (breakiterator_class.h:59-65), `MSG_FORMAT_METHOD_FETCH_OBJECT` (msgformat_class.h), `DATE_FORMAT_METHOD_FETCH_OBJECT` (dateformat_class.h), `DTPATTERNGEN_METHOD_FETCH_OBJECT` (datepatterngenerator_class.h:52-58), `COLLATOR_METHOD_FETCH_OBJECT` + guard baru `collator_check_initialized` (collator_class.h:49-63). Tidak ada metode publik yang menyentuh handle ICU sebelum cek terhadap `NULL` — kasus **pre-init-exec ter-sapu bersih**.
5. **Global `INTL_G(current_collator)` / `INTL_G(compare_func)`** (`collator_sort.c:299,305`) — kandidat R2 klasik (pointer mentah ke `UCollator*` di global module, dipakai di callback `zend_hash_sort()` (`collator_compare_func`, `collator_sort.c:302`)) — **gugur**: (i) di-set ulang setiap pemanggilan `collator_sort_internal` sebelum `zend_hash_sort` dan di-restore tepat setelahnya, (ii) `co` milik `$this` yang hidup selama frame C itu berjalan (objek tidak bisa di-free di tengah sorts frame karena `$this` di-hold stack frame), (iii) `compare_func` di-reset di setiap entry `collator_sort`/`asort`. Pola ini sudah aman untuk skenario nested arbitrary (sort-recursion / nested `Collator::sort` dari callback `__toString`, yang mana PHP 8 tidak men-taint frame `zend_hash_sort` karena seluruh array di-hold oleh `sorted` dup lokal — dan fungsi compare tidak menjalankan user code kecuali melalui `collator_regular_compare_function` → `compare_function` standar Zend yang bisa memicu cast object-to-string — namun cast ini tidak menyentuh `INTL_G(current_collator)` sama sekali — hanya memakai `compare_func` sama yang di-hold di frame — tidak ada kandidat R2 yang tersisa).
   *Catatan:* RSHUTDOWN me-reset global ini (`php_intl.c:256-262`), sementara RINIT `intl` sengaja dikosongi (return SUCCESS saja, `php_intl.c:247-250`) — untuk ekstensi intl ini tidak masalah karena semua global lain bukan pointer request-bound.
6. **Pemakaian `safe_femalloc`/`zend_string_falloc` di `php_converter_do_convert` (`converter.c:640-680`) dan `normalizer_normalize` (`normalizer_normalize.c:148-183`)** — 100% jalur OOM-guard adalah perubahan fallible murni, **gugur** sebagai kandidat R2 (tidak ada pointer mentah melebihi umur pemiliknya — `temp` dan `ret` keduanya di-`efree`/`zend_string_efree` di semua jalur sebelum `return`).
7. **`grapheme_get_break_iterator`** global `INTL_G(grapheme_iterator)` (persistent across requests, di-close di RSHUTDOWN `grapheme_close_global_iterator`) — gugur: hanya dipakai sebagai template `ubrk_clone`/`ubrk_safeClone` per-call (`grapheme_util.c:380-400`), jadi iteratorglobal tidak pernah menyentuh text user; RSHUTDOWN terlebih lagi bersih-bersih (`php_intl.c:257-260`).
8. **`intl_convert_utf16_offset_to_utf8` ekspansi helper baru (8.4.27)** — gugur sebagai kandidat R2/R4: murni perhitungan offset, tanpa alokasi persisting, tanpa menyimpan pointer.

## Kandidat yang gugur (dengan alasan line-numbered)

- **G-1 — `Collator` clone:** `Collator_handlers.clone_obj = NULL` (`collator_class.c:78`) → `clone $coll` lempar Error sebelum menyentuh C state — tidak ada shallow-copy. Gugur.
- **G-2 — `php_converter_clone_object` tanpa `oldobj->src` guard** (`converter.c:936-975`): beda dengan kelas lain yang melempar "Cannot clone uninitialized" — converter clone dari objek setengah-jadi (konstruktor fail) akan memanggil `ucnv_clone(oldobj->src=NULL)` yang kemudian throw `U_ILLEGAL_ARGUMENT_ERROR` dari ICU, dan `php_converter_object_ctor` sudah mentrigger `intl_error_init` bersih — tidak ada dangling `src`/`dest` yang disalin, hanya error yang bahasa errornya kurang informatif. Incremental severity: cosmetics, bukan mem-unsafety. Gugur untuk R2/R4.
- **G-3 — `msgformat_data.arg_types` cache (`HashTable*`)** (`msgformat_data.h:35-39`, cache diisi `msgformat_helpers.cpp:99-124,144-279`, di-invalidate saat `setPattern` `msgformat_attr.c:97-101`): kandidat R2 klasik (hash mentah disimpan di objek, mentorok pattern-updates), tapi gugur karena invalidation tepat di titik satu-satunya yang bisa mengubah tipe args (`setPattern`), dan clone `MessageFormatter` tidak menyalin `arg_types` sama sekali (fresh di sisi clone via `msgformat_data_init` dalam `create_object`) — tidak ada aliasing lintas objek.
- **G-4 — Clone state-loss `IntlDateFormatter`/`MessageFormatter`** (`dateformat_class.c:65-101`, `msgformat_class.c:57-95` pra-8.4.27): kandidat diff → **sudah di-fix di 8.4.27** (patch menambah salin eksplisit field). Verdict (c) known-silent-fix — masuk table triase di atas, bukan temuan baru.
- **G-5 — `Transliterator_clone_obj` fail-path** (`transliterator_class.c:129-155`): utrans_clone gagal → `transliterator_object_destroy(to_new)` (utrans itu NULL-safe di baris 88-92, `to_new->utrans` memang belum di-set — no-op) → throw → decay ke return `retval` dengan utrans NULL bersih (setelah dtor-objek-member yang pertama sudah `zend_object_std_dtor`-only, tidak menyentuh ICU pointer) — jalur borongan aman, tidak ada double-free sama seperti Spoofchecker karena free ICU tidak dipanggil di sini (utrans NULL). Gugur.
- **G-6 — `IntlDateFormatter`/`MessageFormatter` field-loss pre-fix** sama dengan G-4 — duplikat kandidat, ditarik setelah diff.
- **G-7 — `msgformat_fix_quotes` erealloc tanpa cek** (`msgformat_data.c:73-90`): `npattern = erealloc(npattern, ...)` — jika failure hanya OOM, jalur ini butuh OOM-fuzzing untuk menyentuh; sesuai aturan triase operator, murni fallible/OOM → di luar scope R2/R4. Gugur (bukan target).
- **G-8 — `spoofchecker_clone_obj` no-parts adendum** — hanya ada `uspoof` yang sudah di-cover K-1-a; `uspoofres` hanya di-free (`spoofchecker_object_destroy` baris 134-136) dan tidak di-clone — bisa dibilang state-loss (uspoofres di klon NULL) tapi tidak ada pointer jadi tidak R2; untuk R4-accumulator bisa dianggap sama kelas G-4 yang tak tertambal — nilai security-nya kosong (tidak bisa diarahkan ke pointer mentah). Gugur.

## Filter global/global-state R3 — sampingan (bukan target R2/R4 tapi disorot)

`INTL_G(current_collator)`, `INTL_G(compare_func)` — sudah dibahas di bagian bersih #5. `INTL_G(error_level)`, `INTL_G(use_exceptions)`, `INTL_G(error_code)` di-set via ini, tidak ada pointer request-bound. RINIT kosong tidak membuka gap karena tidak ada global pointer-per-request liln di intl selain `current_collator` (sudah prevent-restore) dan `grapheme_iterator` (sudah di-close di RSHUTDOWN).
